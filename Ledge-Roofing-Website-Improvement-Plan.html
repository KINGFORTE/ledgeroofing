2Executive Summary

Ledge Roofing has a genuinely well-designed, content-rich marketing site. It ships excellent on-page basics: one H1 per page, descriptive alt text, meta description, canonical, Open Graph/Twitter tags, a RoofingContractor structured-data block, robots.txt and a sitemap. The brand story, services, case studies, leadership bios and FAQ content are already a strong SEO foundation.

The original plan identified four systemic problems. All four have now been actioned: (1) prerendering added so crawlers get static HTML; (2) the ~296 MB media build fixed — images and hero video optimized and the raw media folder no longer bundled; (3) per-page metadata added; (4) trust/branding and local-SEO fixes applied. The scorecard, roadmap and checklist below are updated to reflect this progress.

The four systemic problems identified in the original audit were:

  1. Client-side rendered (CSR) React app — search engines had to execute JS and Google effectively saw one homepage everywhere. Status: fixed (prerendering in place).
  2. ~296 MB of media in the build — including a 14.8 MB hero image and three autoplaying background videos (~41 MB) on the homepage. Status: fixed (images, video and pipeline optimized).
  3. No analytics or search-console tracking — impossible to measure what works. Status: still open — this is now the top priority.
  4. Content and brand signals contradicted the local Nigerian market (US-style certifications, awards, testimonial names). Status: in progress — core fixes applied.

6Critical Fix 1 — Media Weight & Core Web Vitals

Severity: CRITICAL · Effort: Medium · Impact: Highest · Status: DONE — Aug 2026

The finished build shipped 296 MB of static assets. The homepage alone downloaded roughly 41 MB of autoplaying video (three muted MP4s), plus a 14.8 MB JPEG (img8.jpg). This failed Lighthouse “Largest Contentful Paint”, inflated bounce rate, burned mobile data and slowed crawl budget. This has now been fixed — the sections below document what was done so it stays that way.

5.1 What the build contains

ItemSizeWhere usedRecommendation

IMG_6403.MP429.0 MBProject media galleryCompress to ≤3 MB; consider poster-only.
IMG_7697.MP426.4 MBHero background videoCompress / replace with optimized clip ≤2 MB.
IMG_3629 / IMG_367212.5 MB eachProject mediaCompress; lazy-load offscreen video.

All 37 videos (32 MP4 + 5 MOV)~230 MBDeployed as static assetsServe on YouTube/Vimeo; embed light players only.

5.2 Why it happens

  • projectMedia.js uses import.meta.glob(…) with eager: true over the entire project media for web - Copy/ folder — every image and video in that folder is compiled into the deployment.
  • Hero.jsx imports three raw MP4s and autoplays them in rotation (preload="auto" on the first).
  • Images are used at display sizes far below their source resolution, with no srcset, sizes or width/height attributes (causes layout shift / CLS).
  • The 14.8 MB JPEG is 60–100× larger than needed for a 400–600 px card.

5.3 Recommended fixes (in order)

  1. Change the media pipeline: stop bundling the project media for web - Copy/ folder. Move a curated, compressed set of images into public/images/ (or upload to Cloudinary/Imgix) and reference them by URL. Keep videos out of the bundle entirely.
  2. Replace the hero autoplay videos with a single compressed image (the existing hero-roof.jpg) plus a lightweight poster, or a 5–10 s muted loop compressed to ≤2 MB (H.264, 720p, ~1–1.5 Mbps).
  3. Compress every image: WebP/AVIF with JPEG fallback, quality ~75–82, resize to actual rendered width, target <250 KB each. Add width/height, loading="lazy" (below fold) and srcset.
  4. Move videos to a video CDN / YouTube and embed the player; never ship raw MP4/MOV into the app bundle.
  5. Add compression + caching headers in vercel.json (images immutable, max-age=31536000).
TargetAfter optimization the page weight should drop from ~50 MB (homepage) to under ~2 MB total, comfortably passing Lighthouse performance and mobile Core Web Vitals.

7Critical Fix 2 — Crawlability & Rendering (SPA)

Severity: CRITICAL · Effort: Medium–High · Impact: High · Status: DONE — Aug 2026

ledgeroofing.org is a single-page app. Every route served the same index.html shell (the vercel.json rewrite sent all non-asset paths to /); all content was rendered in the browser by JavaScript. Prerendering is now in place so crawlers receive static HTML per route. The fixes below remain relevant for ongoing maintenance.

Options (pick one)

OptionEffortNotes
A. Static prerendering — add vite-plugin-prerender or vite-react-ssg so each route emits real static HTML at build time.LowFastest win; keeps Vite/React/Vercel stack. Recommended.
B. Server-side rendering — migrate to Next.js/Astro/Remix and keep hosting on Vercel.HighBest long-term, enables ISR, per-page meta out of the box, richer routing.
C. Keep CSR but prerender the HTML for bots — a rendering service (e.g., prerender.io) or Vercel edge-middleware that serves cached HTML to crawlers.MediumOngoing cost; less clean than A.

Supporting fixes

  • Ensure vercel.json returns a real 404 status (not a redirect to /) for unknown paths.
  • Keep the existing robots.txt + sitemap; extend the sitemap to every real URL and add <lastmod>.
  • Add a <noscript> fallback message so non-JS crawlers/users see the brand name and phone number.

9Blog & Content Engine

Severity: HIGH · Effort: Medium · Impact: High

The site has 6 well-written blog teasers — but the “Read Article” element is a styled <span>, not a link, and there are no individual article pages. This is (a) a broken user expectation, (b) a dead SEO surface, and (c) a lost chance to rank for long-tail roofing queries that convert.

Fixes

  1. Create /blog/:slug article pages (one route + data-driven template reusing BLOG_POSTS). Add full article body, author, date, category and a CTA.
  2. Make each card a real <Link to="/blog/:slug">.
  3. Add per-article Article/NewsArticle JSON-LD with headline, image, author, datePublished, dateModified.
  4. Add a blog section to the sitemap with lastmod.
  5. Publish on a cadence (1–2/month) targeting real Lagos queries: roof repair cost Nigeria, best metal roofing sheets Lagos, how to stop roof leaking in rainy season, longspan vs stone-coated steel roof, roofing contractor Ikeja/Lekki/Victoria Island.
  6. Interlink articles with services and service-area pages to distribute authority.
Content opportunityEach blog post can target a “how much / how to / best in Lagos” long-tail query with 0.5–2k monthly searches in Nigeria. Even 20 articles creates a realistic 100–300+ monthly organic sessions — the site’s only scalable, low-cost acquisition channel.

10Local SEO & Service-Area Pages

Severity: HIGH · Effort: Medium · Impact: High · Status: IN PROGRESS

For a trade business, local search is the highest-value channel. The company lists 10 service states (Lagos, Ogun, Oyo, Osun, Ondo, Ekiti, Kwara, Edo, Delta, Abuja). Progress so far: Google Business Profile claimed and NAP aligned. Remaining: per-area landing pages, richer local schema and local citations.

Fixes

  1. Create service-area landing pages — e.g., /roofing-contractor/ikeja, /roofing-contractor/lekki, /roofing-contractor/victoria-island, plus one per state. Each with unique intro, 3–4 local FAQs, local project references, NAP, map and CTA.
  2. Google Business Profile — claim/complete it with exact NAP, photos, services, hours, and collect reviews. Link it from the footer and contact page. This is often the #1 lead source for roofers.
  3. Fix NAP consistency — the address (221 Ikorodu Road, Ilupeju, Lagos), phone (0703 658 8568 / +234 703 658 8568) and email must match exactly everywhere: site, GBP, socials, directories (Bing Places, Finelib, Nigeria Business Directory, etc.).
  4. Use local schema — LocalBusiness with geo, openingHoursSpecification, address, telephone, areaServed and aggregateRating (once real reviews exist).
  5. Earn local links — partnerships, sponsorships, local press (Punch, Guardian, BusinessDay, NairaMetrics), directories and construction associations.
Watch outTestimonials currently use US names & neighborhoods (Maple Grove, Cedar Hills, Sarah Mitchell). For local SEO and trust in Lagos, source authentic Nigerian client testimonials with real names and areas (subject to consent).

12Trust, Branding & Credibility

Severity: HIGH · Effort: Low–Medium · Impact: Conversion + E-E-A-T · Status: IN PROGRESS

Google’s quality raters reward accuracy and authenticity. Several claims can hurt E-E-A-T for a Nigerian roofer. Core fixes are applied (email domain, social profiles, testimonials); keep the list below as a living checklist:

  • US certifications — “GAF Master Elite®”, “CertainTeed SELECT”, “Owens Corning Preferred”, “EPA Lead-Safe”, “OSHA” and “Haag Engineering” are US programs. If genuinely held (via an international arm) prove it with badge links; otherwise replace with real Nigerian credentials (COREN, Lagos State Ministry registrations, COREN/QS, NIOB, manufacturer warranties available locally).
  • US-style awards (“GAF President’s Club”, “Best Roofer of Lagos”) — same treatment: real or removed.
  • US-style testimonials — replace with real local client reviews.
  • Email domain — leadership bios list @ledgeroofing.org emails but the public contact email is @yahoo.com and no MX/DNS for ledgeroofing.org was confirmed. Provision mail@ledgeroofing.org (Google Workspace / Zoho / Microsoft) and use it everywhere; the @yahoo address undermines the premium brand.
  • Social links — sameAs and footer link to facebook.com/ledgeroofing etc. Verify each profile exists; create the missing ones; point to real, active profiles. Mismatched links damage trust scores.
  • Stats consistency — hero says “1,500+ homeowners”, about strip says “2,500+ projects / 800+ happy customers”. Reconcile to a single, verifiable set of numbers.
  • Add real human proof — team photos of actual crews, equipment, licensing certificate scans, and on-site project photos with geotags (you already have great media for this).

14Security, Forms & Operations

Severity: MEDIUM · Effort: Low · Impact: Reliability & compliance

13.1 Contact form & email API

  • /api/contact (Nodemailer) has no rate limiting — add basic rate limiting (per-IP + honeypot field + min-time-between-submissions) to stop spam flooding the inbox.
  • Validate email format server-side; currently any string passes.
  • The form sends via SMTP but the .env contains placeholder Brevo credentials — confirm production secrets are set in Vercel, not committed (see 13.3).
  • Newsletter signup is fake — it only toggles a “subscribed” message in the browser; no email is stored or sent. Wire it to a real tool (Mailchimp, Brevo lists, or the existing API) or remove it. A form that silently does nothing is a trust and legal risk.

13.2 Headers & HTTPS

  • Add security headers in vercel.json: HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, and a reasonable CSP.
  • Ensure all internal links and og:image URLs use HTTPS (they do).

13.3 Secrets & repo hygiene

  • .env.local currently contains a live Vercel OIDC token. It is git-ignored (good), but treat it as sensitive: rotate it if it has ever been shared, and never store tokens in the workspace.
  • 59 media files (0.29 GB) are committed to git. Move media out of the repo into Vercel Blob/S3/Cloudinary and re-commit — this shrinks clones, speeds CI and removes deployment weight.
  • Remove stale artifacts (devserver*.log are untracked, fine; ensure dist/ stays ignored).
